# Domain docs

This repository has a single context. Domain terms live in `CONTEXT.md` at the
root, and architectural decisions live in `docs/adr/`.

## Before exploring

Read `CONTEXT.md` and ADRs relevant to the task. If they do not exist, continue.
The `domain-modeling` skill creates them when terms or decisions need recording.

## Use the glossary's vocabulary

Use the terms defined in `CONTEXT.md` in issues, code, and documentation.
If a needed concept is missing, check whether it belongs in the domain before
proposing an addition through `domain-modeling`.

## Flag ADR conflicts

If a proposal contradicts an accepted ADR, identify the ADR and explain the
conflict before proceeding.
